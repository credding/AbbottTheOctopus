Reactions

Each button sends a POST /reaction with one of the Zoom emoji names mapped to that reaction, exactly as the Zoom App does. Reactions play one at a time: extra clicks queue up, but clicking a reaction that's already queued does nothing. A reaction always takes over the arms and clears manual hold.

One tentacle — POST /arm

Pick a tentacle, then drag. Values are sent live while you drag. 0 = down, 0.5 = neutral, 1 = up. Moving a tentacle puts the arms into manual hold, so the idle animation stops resetting them.

down up
Tentacle 0 → 0.50

All tentacles — POST /arms

One slider per tentacle. The All slider moves every tentacle together. With “Send live” on, every change sends the full set of heights. Turn it off to set up a pose, then press Send pose.

API reference

Every request goes to this server, at . Send POST bodies as JSON with Content-Type: application/json. Client mistakes get a 400 with {"status": "error", "message": "…"}.

POST/reaction: play a reaction

Body: an object whose type is a Zoom emoji name. Other fields (what the Zoom backend sends) are ignored.

{"type": "heart"}
Reactiontype values

Response 200: {"status": "success", "recognized": true, …}. Unknown names still get a 200, with "recognized": false, and are ignored.

POST/arm: set one tentacle
FieldTypeMeaning
tentacleintegerTentacle number, 0–7 (PCA9685 channel). A numeric string like "3" also works.
heightnumber0.0 (down) to 1.0 (up). 0.5 is neutral. Must be a JSON number, not a string.

Response 200: {"status": "success", "set": {"2": 0.75}, "timestamp": "…"}

POST/arms: set several or all tentacles

heights can be a list (the position in the list is the tentacle number, and null leaves that tentacle alone):

{"heights": [0.5, 0.6, 0.5, 0.7, 0.5, 0.5, 0.5, 0.5]}
{"heights": [null, 0.9, null, 0.1]}

…or an object that names only the tentacles to move:

{"heights": {"1": 0.9, "3": 0.1}}

Every value is checked first. If any one is invalid, nothing moves.

Response 200: {"status": "success", "set": {"0": 0.5, "1": 0.6, …}, "timestamp": "…"}

POST/arms/release: back to idle

No body. Leaves manual hold, and the arms return to neutral (0.5) on the next frame.

GET/health and /info

/health → {"status": "healthy", "service": "abbott-combined", "manual_hold": false, …}

/info → {"n_arms": 8, "neutral_height": 0.5, "reactions": {"Love": ["heart", "clap"], …}} (this page uses it to build itself)

How reactions and manual control share the arms
  • Idle: the eyes wander, and the arms sit at 0.5.
  • After /arm or /arms: manual hold. The arms stay where you put them, and the eyes keep wandering.
  • A reaction takes over the arms and clears manual hold. Afterwards the arms return to 0.5, not to your manual pose.
  • /arms/release clears manual hold without playing a reaction.
  • Manual commands sent during a reaction are applied, but the reaction's next frame usually overwrites them.
